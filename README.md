## 获取与阅读

```bash
git clone --branch main https://github.com/heisd/git_code_c.git
cd git_code_c
git status
git log --oneline
```

先阅读 Word 文档，再结合文本文件观察 Git 的工作区、提交和合并概念。此分支没有顶层 CMake/Make 构建配置，因此 README 不提供虚构的编译命令。

## 嵌套仓库引用说明

目录树中的 `git_code_c` 与 `new_people/git_code_c` 是模式为 `160000` 的 gitlink，而不是普通源码文件或完整目录内容。当前树中没有 `.gitmodules` 配置，因此不能仅凭这些引用确定远程 URL，也不能保证执行子模块初始化就能取得内容。

若需要恢复对应项目，应先查清原始仓库地址和引用提交，再配置实际来源。不要把 GitHub 中显示的一条提交引用理解为全部源码已经存在。

## 合并标记练习

`123.txt` 中可看到：

```text
<<<<<<< HEAD
一侧内容
=======
另一侧内容
>>>>>>> 提交标识
```

这是两侧修改的冲突表示。要练习解决冲突，应先理解两侧内容，编辑成最终结果并移除标记，再查看 `git diff`、暂存并提交。当前文件保留这些标记是仓库现状，不表示 Git 正在进行一次尚未结束的合并。

## 常见问题

- **找不到 C 程序入口**：当前分支主要是资料与 Git 练习，不具备统一应用入口。
- **嵌套目录没有源码**：检查 gitlink 与远程映射，不要把它当作普通文件。
- **Word 文档无法网页预览**：下载正文 `学习git.docx` 后阅读。
- **看到冲突标记**：先区分文件中历史保留的文本与当前 Git 工作区是否处于冲突状态。

后续补充 C 示例时，可按知识点建立独立目录，并同时记录源文件、编译步骤和预期输出。
